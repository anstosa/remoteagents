# Review tour and Code review run on a configured agent

The Review tour was generated by one hard-wired command: `codex exec --ephemeral --sandbox read-only --output-schema …` against `adapters.codex.program`, with a fixed prompt and Codex's built-in default model and effort. ADR 0005 kept it on the Codex entry. Three needs broke that. The operator wants to choose the agent, prompt and effort that narrate the tour. They want an opt-in AI **Code review** to run alongside the tour, with its **Findings** shown as suggested inline comments in the tour's diffs. And Claude bills non-interactive (`claude -p`) use separately from interactive use, so whether an agent runs headless must be the operator's choice.

We chose a `review` configuration section. It names a run mode per agent kind, the tour's agent, model, effort and prompt, and a list of **Review presets** for the Code review. Both the tour and the Code review are a **Review run**: one prompt sent to one agent in the Worktree, which must answer with JSON that the server validates. A Review run is either *headless* (a child process with schema-constrained output) or *interactive* (a fresh Agent in the Worktree's Workspace whose final message is the JSON). The run mode is set per agent kind, because that is the axis billing varies on.

## Considered options

- **Headless only.** This is the smallest change. Every Claude-run tour or review would then be billed as non-interactive use, which the operator rejected.
- **Interactive only.** One mechanism, but the tour would open a pane for a one-minute narration even on Codex, where headless costs nothing extra.
- **A run-mode toggle on each run.** The same answer would be chosen every time for a given agent, so it belongs in configuration.
- **Findings included unless dismissed.** This forwards the model's opinion as the operator's own and turns false positives into work for the implementation agent. Findings are suggestions the operator must Keep.
- **A Code review without a tour, shown in the Code panel.** Deferred. The tour's steps and diffs are what Findings anchor on today.

## Decisions

- **Configuration.** The section looks like this:
  ```json
  "review": {
    "agents": { "claude": { "mode": "interactive" }, "codex": { "mode": "headless" } },
    "tour": { "agent": "codex", "model": "…", "effort": "low", "prompt": "…" },
    "defaultPreset": "correctness",
    "presets": [{ "id": "correctness", "label": "Correctness", "agent": "claude", "effort": "high", "prompt": "…" }]
  }
  ```
  Every field is optional. The tour defaults to Codex when `adapters.codex` is configured, else Claude, with a built-in prompt. With no presets, one built-in "Correctness" preset runs on the tour's agent. Only `codex` and `claude` kinds can run a Review run. A preset or tour naming an unconfigured agent, an effort that agent does not accept, a duplicate preset id or an unknown `defaultPreset` fails config validation.
- **Effort levels are per agent.** Codex accepts `minimal | low | medium | high | xhigh` (`-c model_reasoning_effort=…`). Claude accepts `low | medium | high | xhigh | max` (`--effort`). The model is configuration only (`-m` / `--model`).
- **A configured prompt says what to look for. The server owns the contract.** After the operator's prompt, the server always appends the Change list with IDs and patches, the output shape, and the rules the parser enforces. For the tour that rule is "assign every Change ID exactly once". For the Code review it is "anchor each Finding to a Change ID and a line range inside that hunk". A custom prompt cannot break the parser.
- **A Review run cannot modify the Worktree.** An edit would make the tour stale. Headless Codex keeps `--sandbox read-only`. Headless Claude runs with `--tools Read,Grep,Glob` and no session persistence. An interactive run gets the same restrictions as per-launch arguments.
- **An interactive run is a visible Agent.** It launches fresh in the Worktree's Workspace, named `🗺 Tour · <branch>` or `🔍 Review · <preset label>`, and never takes focus. It is listed among the Place's Agents so the operator can watch it or answer a question. Its final message is read from the agent's own transcript: Codex's `task_complete.last_agent_message`, or the last assistant message in Claude's session JSONL. Output that fails validation gets one correction prompt in the same conversation. The pane closes when the run succeeds. It stays open when the run asks a question, times out, or fails validation twice. A question notifies the operator. A normal completion does not, because the tour's ready indicator already covers it.
- **The Code review is opt-in and off by default.** It runs only together with a tour: started with one, or added to a current stored tour with "Add AI review". It uses the tour's Comparison, including the tour's Tests and Docs choice, so every Finding can anchor. Each Worktree has at most one Code review job, and starting a new one replaces the old. It has its own limits: a 15-minute run timeout and a job lifetime longer than the tour's.
- **Findings.** Each Finding is `{ changeId, side, startLine, endLine, severity: high | medium | low, title, body }`. A Finding whose Change ID is unknown, or whose lines fall outside that hunk's range on that side, becomes a **general Finding** instead of being dropped. Findings are published even when the Worktree changed during the run. Change IDs are content digests, so a Finding can only attach to the exact hunk it was written against. Findings are stored with the stored tour and cleared with it.
- **Starting.** The Review button opens a start sheet. It holds the scope (Working / All PR, defaulting to the Git flyout's mode), Tests and Docs, the tour's effort, and the opt-in Code review with its preset, effort and an optional "extra focus" note. The extra focus is appended to the preset prompt for that run only. The Code review is unchecked on every open. The preset and effort default to the last ones used on that device. Opening an existing tour skips the sheet. The tour dialog's own Tests and Docs filters are removed: changing the Comparison means starting again.
- **Triage.** A Finding shows as a suggested comment on its diff lines, with its severity, title, body and source, and offers Keep or Dismiss. Keep turns it into an ordinary inline comment, pre-filled and open for editing. From then on it is the operator's own comment, with no attribution in the change request. Untriaged Findings are never sent. The summary counts them and links back. Steps holding Findings show a count. General Findings are listed on the tour's first step and on the summary, also with Keep or Dismiss. Triage state lives in the browser, like inline comments.

## Consequences

- **This supersedes ADR 0005's "Review tour stays on the Codex entry" bullet.** The tour reads its agent from `review.tour`. An OMX-only configuration can now generate tours with Claude.
- **The capability check is per agent.** The dashboard reports whether the tour's agent is runnable, and lists each preset with its own availability and reason. A preset whose agent is unavailable is shown disabled.
- **Launches gain per-launch arguments.** Interactive runs need effort, model and read-only flags on one launch only. Operator arguments from `adapters.<kind>.args` still apply.
- **A costly run can be published against a stale tour.** The operator sees the tour's existing stale state and decides whether to regenerate.
